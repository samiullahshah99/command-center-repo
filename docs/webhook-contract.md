# Command Center — Inbound Webhook Contract

**For: Portal and Studio platform owners.**
**Status: implemented and live on our side. Ready for you to send against.**

This document is everything needed to send events to Command Center. It assumes
no knowledge of our codebase.

---

## 1. Endpoints

| Platform | URL |
| --- | --- |
| Portal | `https://command-center-repo-production.up.railway.app/api/webhooks/portal` |
| Studio | `https://command-center-repo-production.up.railway.app/api/webhooks/studio` |

- `POST` for events.
- `GET` returns `{"ok":true,...}` — use it to confirm the endpoint is reachable
  before wiring anything up.
- No authentication cookie or bearer token. **The signature is the auth.**

---

## 2. Headers

Every POST must include both:

| Header | Value |
| --- | --- |
| `X-CC-Signature` | Lowercase hex HMAC-SHA256. **No prefix**, no `sha256=`, no `v0=`. |
| `X-CC-Timestamp` | Unix time in **seconds** (not milliseconds). |
| `Content-Type` | `application/json` |

---

## 3. Signature

### Basestring

```
v0:{X-CC-Timestamp}:{raw request body}
```

`v0:` is a literal scheme version and **is part of the signed string**. The two
colons are literal separators.

### Algorithm

```
X-CC-Signature = hex( HMAC_SHA256( shared_secret, basestring ) )
```

> ⚠️ **Sign the exact bytes you send.** Serialise your JSON once, sign that
> string, and send that same string. Do not re-serialise between signing and
> sending — a different key order or different whitespace produces a different
> HMAC, and the request will be rejected with a signature mismatch that looks
> exactly like a wrong secret. This is the single most common integration bug.

### Worked example

Using the **dummy** secret `test_secret_do_not_use`:

```
secret     = test_secret_do_not_use
timestamp  = 1785000000
body       = {"event_id":"evt_1","event_type":"demo.event","occurred_at":"2026-07-31T09:00:00.000Z","data":{}}

basestring = v0:1785000000:{"event_id":"evt_1","event_type":"demo.event","occurred_at":"2026-07-31T09:00:00.000Z","data":{}}

X-CC-Signature = 6c68240306f794d53efe4fe76906d13c9067b3c458f0fb22a8f23ee6c9b225d8
```

**That value is real, not illustrative** — it was generated by the same code that
verifies your requests. Feed those exact inputs into your implementation; if you
get that hex, you are correct. If you do not, the mismatch is in your code, not
in the secret.

Check it in one line:

```bash
printf 'v0:1785000000:{"event_id":"evt_1","event_type":"demo.event","occurred_at":"2026-07-31T09:00:00.000Z","data":{}}' \
  | openssl dgst -sha256 -hmac 'test_secret_do_not_use' -hex
```

**Reference implementations**

```bash
# bash
BODY='{"event_id":"evt_1","event_type":"demo.event","occurred_at":"2026-07-31T09:00:00.000Z","data":{}}'
TS=$(date +%s)
SIG=$(printf 'v0:%s:%s' "$TS" "$BODY" | openssl dgst -sha256 -hmac "$SECRET" -hex | sed 's/^.* //')

curl -X POST https://command-center-repo-production.up.railway.app/api/webhooks/portal \
  -H "Content-Type: application/json" \
  -H "X-CC-Timestamp: $TS" \
  -H "X-CC-Signature: $SIG" \
  --data "$BODY"
```

```python
import hmac, hashlib, time, json, requests

secret = os.environ["CC_WEBHOOK_SECRET"]
body   = json.dumps(payload, separators=(",", ":"))   # serialise ONCE
ts     = str(int(time.time()))
sig    = hmac.new(secret.encode(), f"v0:{ts}:{body}".encode(), hashlib.sha256).hexdigest()

requests.post(url, data=body, headers={          # data=, not json=
    "Content-Type": "application/json",
    "X-CC-Timestamp": ts,
    "X-CC-Signature": sig,
})
```

```javascript
import { createHmac } from 'node:crypto';

const body = JSON.stringify(payload);              // serialise ONCE
const ts = String(Math.floor(Date.now() / 1000));
const sig = createHmac('sha256', secret).update(`v0:${ts}:${body}`).digest('hex');

await fetch(url, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-CC-Timestamp': ts,
    'X-CC-Signature': sig
  },
  body                                              // the SAME string that was signed
});
```

## 4. Shared secret

- One secret per platform: `PORTAL_WEBHOOK_SECRET`, `STUDIO_WEBHOOK_SECRET`.
- Generate with `openssl rand -hex 32`.
- Exchange out of band — **not** over email or Slack. Never commit it.
- To rotate: we accept the old and new secret simultaneously for a changeover
  window. Tell us before you switch.

---

## 5. Payload envelope

```jsonc
{
  "event_id":    "evt_portal_01HQ8X3K2M4N5P6Q7R8S9T",  // unique, stable across retries
  "event_type":  "returns.acknowledged",                // dotted namespace
  "occurred_at": "2026-07-31T09:14:22.481Z",            // ISO 8601, UTC, with timezone
  "data":        { }                                    // free-form, your shape
}
```

| Field | Rules |
| --- | --- |
| `event_id` | **Required.** Must be unique per event and **identical across retries of the same event.** This is how we deduplicate — see §6. A UUID or ULID is ideal. Do **not** reuse a record id: one record produces many events. |
| `event_type` | **Required.** Dotted namespace, e.g. `returns.acknowledged`, `brief.submitted`. |
| `occurred_at` | **Required.** ISO 8601 with timezone. When the event happened in your system, not when you sent it. |
| `data` | **Required** (may be `{}`). Free-form — we store it verbatim and do not parse it at ingest. Send the whole thing rather than a trimmed subset; we would rather have too much. |

We store the entire body unchanged. Additional top-level fields are preserved.

---

## 6. Retry behaviour — required

| Our response | What it means | What you should do |
| --- | --- | --- |
| `200` | Stored. | **Stop. Do not retry.** |
| `400` | Malformed JSON. | Do not retry — it will fail again. Alert. |
| `401` | Signature/timestamp rejected. | Do not retry blindly. Check secret, clock, and that you signed the exact bytes sent. |
| `500` | We failed to store it. | **Retry.** |
| timeout / connection error | Unknown. | **Retry.** |

**Required retry policy for 5xx and timeouts:** at least 3 attempts with
exponential backoff — roughly immediate, +1 minute, +5 minutes.

**Retries must reuse the same `event_id`.** We deduplicate on
`(source, event_id)` with a database uniqueness guarantee, so a retry of an
already-stored event is safely ignored and still answered `200`. A retry with a
*new* `event_id` creates a duplicate record we cannot detect.

**Timeout:** respond-time budget is 3 seconds. We persist before responding, so
a `200` means the event is durably stored.

---

## 7. Timestamp / replay window

`X-CC-Timestamp` must be within **±5 minutes** of our server clock. Outside that
window we return `401`.

The check is absolute in both directions — a timestamp in the future is rejected
just as a stale one is. **Keep your servers on NTP.** Clock drift shows up as
intermittent `401`s that look like a wrong secret.

## 8. Also required: a pull endpoint for backfill

Webhooks alone are not sufficient. If your service is down, ours is down, or a
delivery is dropped, there is no way to recover the gap — and webhook delivery is
best-effort by nature.

**Please also expose:**

```
GET /events?since=<ISO 8601 timestamp>&limit=<n>&cursor=<opaque>
```

Returning the same envelopes as §5:

```jsonc
{
  "events": [ { "event_id": "...", "event_type": "...", "occurred_at": "...", "data": {} } ],
  "next_cursor": "opaque-string-or-null"
}
```

Requirements:

- **Ordered by `occurred_at` ascending**, so pagination is stable.
- **Same `event_id` values as the webhook** sent for the same events — that is
  what lets us reconcile without creating duplicates.
- Cursor pagination, with `next_cursor: null` on the last page.
- Authenticated however suits you (bearer token is fine) — tell us the scheme.

This is what makes the integration recoverable rather than merely live. Without
it, a two-hour outage is permanent data loss.

## 9. Checklist before you go live

- [ ] `GET` on the endpoint returns `{"ok":true}`
- [ ] Shared secret exchanged out of band and stored as an env var
- [ ] Body serialised **once** and the identical string is both signed and sent
- [ ] `X-CC-Timestamp` in **seconds**, not milliseconds
- [ ] Signature is bare lowercase hex, no `sha256=` or `v0=` prefix
- [ ] `event_id` stable across retries
- [ ] Retries on 5xx/timeout only, with backoff
- [ ] Servers on NTP
- [ ] `GET /events?since=` implemented for backfill

Send one event against a test secret first. We will confirm it landed.
